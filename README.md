# Refark — избранные реализации

Фрагменты исходного кода Refark — приложения для управления задачами и работой AI-агентов. Подборка показывает выполнение задач в Docker, координацию воркеров и связь серверных событий с интерактивным интерфейсом.

Это материалы для просмотра кода, а не самостоятельное приложение. Часть импортов ссылается на закрытые модули исходного проекта; зависимости, конфигурация и данные для запуска намеренно не включены. Структура путей сохранена.

## 1. Выполнение задач в Docker

- [docker-runner.ts](src/agents/docker-runner.ts) — запуск контейнера, ограничения CPU/RAM/числа процессов, снятие Linux capabilities, запрет повышения привилегий, монтирование входных файлов, обработка ошибок и удаление контейнера в `finally`.
- [agent.Dockerfile](agent.Dockerfile) — образ с отдельным пользователем для выполнения агента.
- [agent-entrypoint.sh](agent-entrypoint.sh) — подготовка рабочего дерева, запуск агента, checkpoint-коммиты и передача результата через маркеры в stdout.
- [process.ts](src/utils/process.ts) — управление дочерним процессом, потоками вывода, таймаутом, отсутствием активности и отменой.
- [task-run-cancellation.ts](src/agents/task-run-cancellation.ts) — остановка выполнения через `AbortSignal` при изменении состояния задачи.

Повторные запуски контейнера используют общий deadline. Для GitHub-проектов credentials передаются через подключаемые файлы; их содержимое в подборку не входит. Docker здесь показан как механизм запуска и ограничения ресурсов, а не как гарантия полной изоляции недоверенного кода.

## 2. Оркестрация задач

- [worker-pool.ts](src/orchestrator/worker-pool.ts) — пулы воркеров по пользователям и ролям, изменение размера пула, heartbeat блокировок и завершение работы.
- [task-manager.ts](src/orchestrator/task-manager.ts) — выбор доступной задачи, зависимости, захват и освобождение блокировки, сохранение состояния.
- [pipeline.ts](src/orchestrator/pipeline.ts) — переходы между разработкой, review и QA, обработка ошибок и ручная передача задачи на следующую стадию.
- [retry-policy.ts](src/orchestrator/retry-policy.ts) и [errors.ts](src/utils/errors.ts) — ограничения повторных попыток, задержки и классификация ошибок.
- [leader-lock.ts](src/orchestrator/leader-lock.ts) — получение и продление lease оркестратора через SQLite.

Здесь можно проследить, как состояние задачи связывается с работающим воркером и как временные ошибки возвращают задачу в очередь.

## 3. События от backend до React

Путь обновления: выполнение агента → событие сервера → SSE → обработчик браузера → обновление данных и интерфейса.

- [live-run-progress.ts](src/agents/live-run-progress.ts) и [progress-detector.ts](src/agents/progress-detector.ts) — извлечение и публикация прогресса выполнения.
- [event-bus.ts](src/web/event-bus.ts) — типы событий и серверная шина.
- [events.ts](src/web/routes/events.ts) — SSE endpoint, фильтрация событий по пользователю при включённой OAuth-конфигурации и keep-alive.
- [useEventSource.ts](web/src/api/useEventSource.ts) — получение событий и инвалидация кеша React Query.
- [useLiveOfficeEvents.ts](web/src/hooks/useLiveOfficeEvents.ts) — состояние событий для интерфейса.
- [useAgentProgress.ts](web/src/hooks/useAgentProgress.ts) — подписка компонентов на прогресс задач.

## 4. Интерактивный pipeline

- [PipelineCanvas.tsx](web/src/components/Dashboard/PipelineCanvas.tsx) — расположение стадий и воркеров, связи между узлами, выбор элементов, перетаскивание, масштабирование и сохранение расположения в localStorage.
- [AgentProgressBar.tsx](web/src/components/UI/AgentProgressBar.tsx) — отображение прогресса агента.

Интерфейс связывает задачи, стадии и работающих агентов в одном представлении. Стили, переводы и остальная оболочка приложения не включены.

## Границы публикации

Исходники скопированы без рефакторинга и исправлений; удалены поясняющие комментарии и лишние пустые строки. Сохранены shebang и техническая директива ShellCheck. Подборка отражает существующую реализацию, включая её ограничения.

Не включены:

- `.env` и его варианты, конфигурация развёртывания и значения credentials;
- базы данных, пользовательские рабочие каталоги, логи, архивы и изображения;
- хранилище авторизации, внутренние промпты, настройки провайдеров и биллинг;
- история исходного Git-репозитория и внутренние документы.

Импорты отсутствующих модулей оставлены, чтобы сохранить исходный код. Названия переменных окружения, параметры токенов и стандартные пути внутри контейнера сохранены: они описывают механизм интеграции и не содержат секретных значений. В выбранных файлах не обнаружено значений, требующих дополнительного удаления из исполняемого кода.

Перед публикацией выполнены проверка на совпадения со значениями секретов из локальных env-файлов, поиск характерных форматов токенов, приватных ключей и внутренних адресов, проверка синтаксиса Bash и сравнение TypeScript до и после удаления комментариев. Приложение не запускалось; эти проверки не являются полным аудитом безопасности системы.
